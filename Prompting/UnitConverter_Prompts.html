Git 브랜치 — Prompt

브랜치는 각 Phase 작업 시작 직전에만 생성 (정책 표) · 아래 복붙 Prompt만 Cursor에 사용.

참고 · Git

브랜치 정책 (워크북 · 수업 운영)

· 작업 시작 직전에만 분기 — 다음 Phase 들어가기 바로 전에 해당 GIT-P 실행 · 미리 일괄 생성하지 않음
· 분기(복사)만 — git checkout -b · 부모 브랜치 시점에서 새 브랜치
· 수업 중 merge 안 함 — 만든 브랜치는 삭제하지 않고 유지
· 정책 변경 — 중간에 브랜치 규칙이 바뀔 수 있음 → 그때까지는 필요한 브랜치만 생성
· 리뷰·수정 — 피드백은 해당 Phase 브랜치 checkout 후 commit (GIT-P8)
· commit — 사용자 채팅 요청 시만 (Rule · Hook)
· RED(red) — pytest FAIL · merge 대상 아님

main ──(명세 시작 직전)──► staging ──(PRD 시작 직전)──► spec ──(RED 직전)──► red ──(GREEN 직전)──► green ──(REFACTOR 직전)──► refactoring ──(EXT 직전)──► new_features ※ 각 화살표 = 그 Phase 들어가기 직전에만 checkout -b · merge 없음 · 만든 브랜치는 유지

Agent

Cursor Agent에 붙여넣기
UnitConverter git 브랜치 점검만. merge·코드 수정·새 브랜치 생성 금지.

1. git branch --show-current  → 지금 하려는 Phase와 일치?
2. git branch  → 존재하는 브랜치 목록 (아직 안 만든 Phase 브랜치는 없어도 됨)
3. git status -sb
4. 현재 Phase에 맞는 pytest (red=FAIL, green/refactor=PASS 등)

표: 현재 브랜치 | 기대 Phase | pytest | 다음에 필요하면 GIT-P?

Cursor Agent에 붙여넣기
팀 리뷰 피드백을 반영해줘. merge·브랜치 삭제 금지.

리뷰 대상 Phase: [spec | red | green | refactoring | new_features]
피드백 요약: [여기에 붙여넣기]
