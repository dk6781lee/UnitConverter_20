## 1. 프로젝트 개요

| 항목 | 내용 |
|------|------|
| 저장소 | [UnitConverter_20](https://github.com/dk6781lee/UnitConverter_20) |
| 유형 | Python CLI 길이 단위 변환기 |
| 시드 파일 | `UnitConverter.py`, `README.md`, `unit-converter.jpg` |
| 현재 상태 | 단일 파일 프로토타입 — OCP/SRP·테스트·설정 외부화 미구현 |

### 프로그램 정의 (README)

- 입력: `{unit}:{value}` 한 줄 (예: `meter:2.5`)
- 출력: 등록된 **모든** 단위로 변환 결과
- 기준 허브: **meter** — feet/yard는 meter 경유
- 비율: `1 meter = 3.28084 feet`, `1 meter = 1.09361 yard`

## 2. 현재 구조 — 입력→처리→출력

**한 줄 흐름**

> `input("unit:value")` → `:` 분리·`float` 파싱 → `if/elif`로 meter 기준 환산 → `print` 3줄 (meter/feet/yard)

```
L2  input()
  → L4~14  파싱·형식/숫자 검증
  → L16~24 단위별 meter 환산 (if/elif)
  → L26~28 feet/yard 재환산
  → L30~32 stdout 출력
```

## 3. OCP / SRP 위반 지점

| # | 위치 | 위반 | 근거 | FR/NFR |
|---|------|------|------|--------|
| 1 | L16~24 `if/elif unit` | **OCP** | 단위 추가마다 분기·비율 하드코딩 수정 필요 | **NFR-01** |

## 4. FR-01~05 충족 여부 (레거시)

| ID | 요구 | 판정 | 근거 |
|----|------|------|------|
| **FR-01** | `meter:2.5` → unit, value | **△ 부분 충족** | `split(':',1)` + `float()` 동작. 공백 trim·빈 unit/value·다중 `:` 정책 미정의 |
| **FR-02** | 전 단위(meter/feet/yard) 출력 | **△ 부분 충족** | 3단위 출력하나 **표시 형식·반올림** README/PRD 불일치 |
| **FR-03** | 미등록 `cubit:1` → 명확한 오류 | **✓ 충족** | `Unknown unit: cubit` 출력 후 종료 |
| **FR-04** | `meter:-1` 음수 거부 | **✗ 미충족** | `-1.0` 그대로 3줄 변환 출력 |
| **FR-05** | 형식 오류 `meter` / `abc` | **△ 부분 충족** | `:` 없으면 `Invalid format…`. PRD E001/E002 메시지 SSOT·세분화 없음 |

**요약:** FR-03만 완전 충족. FR-04 명확 미충족. FR-01/02/05는 기능은 있으나 **계약(표시·에러 문구·정책) 미달**.

### 엣지 케이스 실행 증거

| 입력 | 결과 |
|------|------|
| `meter:2.5` | 3줄 변환 출력 (아래 §5) |
| `meter:-1` | `-1.0 meter = …` 3줄 출력 (거부 없음) |
| `meter` | `Invalid format. Use unit:value …` |
| `abc` | `Invalid format. Use unit:value …` |
| `cubit:1` | `Unknown unit: cubit` |
| `meter:abc` | `Invalid number: abc` |

## 5. `meter:2.5` — 실제 출력 vs README 기대

### 실행 결과

```
Insert value for converting (ex: meter:2.5): 2.5 meter = 2.5 meter
2.5 meter = 8.2021 feet
2.5 meter = 2.734025 yard
```

### README 기대

```
2.5 meter = 8.2 feet
2.5 meter = 2.7 yard
...
```

| 항목 | README/PRD | 레거시 | 차이 |
|------|------------|--------|------|
| feet | **8.2** (소수 1자리) | 8.2021 | 반올림·자릿수 규칙 없음 |
| yard | **2.7** (소수 1자리) | 2.734025 | 동일 |
| meter 줄 | 예시에 없음(…) | `2.5 meter = 2.5 meter` 포함 | 입력 단위 자기 자신도 출력 |
| Domain 정밀 | 8.20210 ft (5자리, 내부) | float 전체 노출 | Domain vs Boundary 분리 없음 |

계산 자체는 README 비율과 일치: `2.5 × 3.28084 = 8.2021`, `2.5 × 1.09361 = 2.734025`.

## 6. 리팩터링 후 BCE 레이어 후보

| 컴포넌트 | BCE | 역할 | 레거시 대응 |
|----------|-----|------|-------------|
| **Parser** | **Boundary** | `unit:value` 파싱, FR-04/05 검증, `ParsedInput` DTO | L4~14 |
| **Registry** | **Entity** | 단위·`metersPerUnit` SSOT, OCP 확장점 | L16~24 분기 + 비율 상수 |
| **Converter** | **Entity** | meter 허브 환산 (순수 함수, I/O 없음) | L16~28 계산 |
| **Formatter** | **Boundary** | 소수 1자리 반올림(RG-04), JSON/CSV/table (EXT-03) | L30~32 |
| **CLI** | **Control** | Parser→Registry→Converter→Formatter 오케스트레이션 | L1~2, L36 |

```
CLI (Control)
  → Parser (B) → Converter (E) ← Registry (E)
  → Formatter (B) → stdout
```

품질 요구(OCP/SRP)와 추가 요구(설정 외부화·동적 등록·포맷)는 **Registry + Formatter + Boundary Parser** 분리로 흡수.

## 8. Git · 브랜치 정책

### 브랜치 흐름 (SSOT)

```
main ──(명세 시작 직전)──► staging ──(PRD 시작 직전)──► spec
                              ──(RED 직전)──► red ──(GREEN 직전)──► green
                              ──(REFACTOR 직전)──► refactoring ──(EXT 직전)──► new_features
```

### 규칙

| 규칙 | 내용 |
|------|------|
| **생성 시점** | 각 Phase **들어가기 직전에만** `checkout -b` |
| **merge** | 없음 |
| **삭제** | 없음 — 만든 브랜치는 **유지** |
| **미리 생성** | 다음 Phase 브랜치는 **지금 만들지 않음** |

### Phase ↔ 브랜치

| 전환 | 브랜치 | Phase | 상태 |
|------|--------|-------|------|
| main → | **staging** | 명세 Phase 시작 | ✅ 완료 |
| staging → | **spec** | PRD·8계층 (GIT-P2 후) | ⏳ 다음 |
| spec → | **red** | RED | — |
| red → | **green** | GREEN | — |
| green → | **refactoring** | REFACTOR | — |
| refactoring → | **new_features** | EXT | — |
